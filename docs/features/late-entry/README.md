# Дозаявка после жеребьёвки

## Зачем

Участник может прийти уже после жеребьёвки, когда стартовый протокол составлен, номера и чипы выданы. Раньше его можно было добавить только в самый конец протокола: время «последний старт + интервал» часто получалось через час-два, а иногда и в прошлом. Дозаявка ставит опоздавшего в ближайшую свободную стартовую минуту по тем же правилам, по которым проводилась жеребьёвка.

## Как пользоваться

**Android**: Центр → соревнование → «Участники» → вкладка группы → «+».
**Web**: «Управление» → соревнование → «Участники» → «+ Добавить».

Если жеребьёвка уже проведена, в форме нового участника появляется блок **«Стартовое время»**:

- **Свободная минута · ЧЧ:ММ** (по умолчанию) — ближайшая минута, свободная по правилам проведённой жеребьёвки и не раньше чем через 2 минуты от текущего момента (запас на запись чипа и путь до старта).
- **В конец · ЧЧ:ММ** (web: «В конец протокола») — сразу после последнего старта протокола.
- **Вручную** — время вводит организатор (Android: `ЧЧ:ММ` или `ЧЧ:ММ:СС`, web: поле времени).

Время в подписях — предпросмотр на момент открытия формы. Окончательное время считается при нажатии «Добавить участника» / «Добавить»: если за это время минута успела пройти, участник встанет в следующую свободную. На Android форма после добавления остаётся открытой, и предпросмотр пересчитывается для следующего участника.

Стартовый номер — следующий после максимального по всему соревнованию. На web он подставляется в поле «Номер старта», и его можно изменить.

## Правила и граничные случаи

**Какая минута «свободна»** — зависит от режима жеребьёвки:

| Режим | Минута свободна, если |
|---|---|
| Общая | в эту минуту никто не стартует |
| По группам | в эту минуту не стартует никто из той же группы |
| По дистанциям | занято меньше коридоров, чем задано при жеребьёвке, и ближе зазора нет участника той же дистанции (группы одной дистанции считаются вместе) |
| Неизвестен (жеребьёвка до 09.10.2026) | коридоров занято меньше, чем максимум в текущем протоколе, и в эту минуту нет участника той же дистанции |

- Протокол рассматривается как сетка минут с шагом «Интервал старта» от самого раннего старта. При запуске соревнования времена сдвигаются целиком, поэтому сетка сохраняется. Время, введённое вручную не по сетке, занимает ближайшую минуту.
- Участники со статусом «Не стартовал» свою минуту не освобождают.
- Если в протоколе ещё нет стартов, отсчёт идёт от времени старта соревнования.
- **Sportiduino**: номер чипа дозаявленного равен его стартовому номеру, как у всех после жеребьёвки. Чип с этим номером нужно записать («Станции и чипы» → вкладка «Номер») — или выдать готовый чип и поменять номер в «Выдаче чипов».
- **«Выдача чипов»** (Android) доступна до завершения соревнования, в том числе после запуска: в ней можно вписать или поменять номер чипа любому участнику и отметить выдачу. Сохраняются только номер чипа и отметка выдачи — поверх свежих данных участника, поэтому параллельные изменения (считывание чипов, синхронизация) не затираются.
- **«По стартовой станции»**: блока нет — жеребьёвки нет, время берётся из отметки на стартовой станции.
- До жеребьёвки участники добавляются как раньше: номер и время внутри группы. На web до жеребьёвки номер и время при добавлении не спрашиваются — участник сохраняется с номером 0 и временем 0 («не назначено», как при самостоятельной регистрации), их назначит жеребьёвка. При редактировании поля есть всегда (пустые, если не назначены) — так номер задаётся, если жеребьёвку не проводят. При старте по стартовой станции номер при добавлении вводится вручную, как раньше.
- **Номер 0 — «не назначен».** Сервер хранит неназначенный стартовый номер как 0. Android при разборе ответов сервера превращает 0 в пустой номер и показывает «—»: в списке участников группы (вкладка «События»), в «Центре» и на экране жеребьёвки (раньше там был «0» или порядковый номер строки, который легко спутать с настоящим номером и номером чипа). На сервер пустой номер уходит снова как 0. Web делает то же в `resultRepository` (`toParticipant`): номер 0 становится `null` и показывается «—» в стартовом протоколе и «Управление» → «Участники», а «№0» не выводится в результатах и на странице сплитов. Остальные номера web приводит к строке — сервер присылает их числом. Жеребьёвка нумерует с 1.
- **Время старта 0 — «не назначено».** До жеребьёвки сервер хранит время старта как 0. Android отправляет таких участников в конец стартового протокола группы. Web в `resultRepository` (`toParticipant`) превращает 0 в `null`: в стартовом протоколе время и стартовая минута («Интервал») показываются как «—». Раньше там выводилась полночь UTC в часовом поясе соревнования (например, «04:00») и минута «01:00».
- **Удаление после жеребьёвки** (Android) больше не сдвигает номера и времена остальных участников группы: номера сквозные и уже выданы.

## Для организатора

Режим жеребьёвки и её параметры (коридоры и зазор для «по дистанциям») сохраняются в соревновании и синхронизируются с сервером. Поэтому дозаявка на сайте работает по тем же правилам, хотя сама жеребьёвка проводится только в Android. Повторная жеребьёвка перезаписывает режим.

## Как устроено

**Модель**: у соревнования ориентирования три новых поля — `drawMode` (`GENERAL` / `GROUP` / `DISTANCE`, null — жеребьёвка не проводилась), `drawCorridors`, `drawGap`. В запросе null у `drawMode` означает «не менять»: веб и редактор соревнования их не присылают.

- **eSport**: колонки `draw_mode`, `draw_corridors`, `draw_gap` в `orienteering_competitions` (`data/database/entity/OrienteeringCompetitions.kt`, `ALTER TABLE` в `data/database/Databases.kt`); enum `domain/orienteering/DrawMode.kt`; поля в `OrienteeringCompetitionRequest` / `OrienteeringCompetitionResponse`; сохранение в `OrienteeringCompetitionService` (null — оставить текущее).
- **Android**:
  - `domain/.../orienteering/DrawSettings.kt` — `DrawMode`, `DrawSettings`; поле `OrienteeringCompetition.drawSettings`.
  - Room: колонки `drawMode`, `drawCorridors`, `drawGap` (миграция `MIGRATION_56_57`). `OrienteeringCompetitionLocalRepositoryImpl.updateCompetition` не даёт затереть флаг и режим жеребьёвки моделью без них (редактор соревнования, старые ответы сервера).
  - Из ответа сервера `isDrawConducted = drawMode != null`, поэтому флаг жеребьёвки больше не сбрасывается при синхронизации. Поэтому же `OrienteeringEventControlViewModel` берёт только этот флаг: прежний запасной признак «у кого-то есть стартовый номер» убран — номер даётся уже при добавлении участника, и «Выдача чипов» / «Стартовая решётка» открывались до жеребьёвки.
  - `DrawViewModel` сохраняет режим через `OrienteeringCompetitionInteractor.setDrawConducted(competitionId, DrawSettings)`.
  - `feature/center/.../data/draw/LateEntry.kt` — `LateEntrySlotFinder` (чистая логика, тесты `LateEntrySlotFinderTest`), `LateEntryPlacement`, `LATE_ENTRY_PREPARATION_MS`.
  - `ParticipantListViewModel` — расчёт времени, номера и чипа при `CreateNewParticipant`, предпросмотр `ParticipantListState.lateEntry`. `ParticipantListScreen` — чипы выбора в `CreateParticipantDialogContent`.
- **Web** (`competra-web-ts`): `src/lib/lateEntry.ts` — порт `LateEntrySlotFinder` (логика должна совпадать); поля `drawMode` / `drawCorridors` / `drawGap` в `OrienteeringCompetition` (`src/types/competition.ts`); выбор времени в `src/features/management/ParticipantEditorDialog.tsx` (получает `participants` из `ParticipantsManageTab.tsx`).

## Ограничения и что не вошло

- Вакантные места при жеребьёвке (резерв минут под возможных опоздавших) не делаются. Если понадобятся, их можно добавить как ещё одно правило в `LateEntrySlotFinder`.
- Минута участника «Не стартовал» не переиспользуется.
- На web для соревнований, разыгранных до появления `drawMode`, сервер не знает о жеребьёвке: форма добавления считает, что жеребьёвки ещё не было, и сохраняет участника без номера и времени — задайте их при редактировании.
