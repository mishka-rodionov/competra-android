# Формат на уровне дистанции

## Зачем

Раньше направление («В заданном направлении» / «По выбору» / «Маркированная трасса») задавалось одно на всё соревнование. Организаторам нужно разное направление в одном соревновании: например, М21 — в заданном направлении, М12 — по выбору. Теперь у соревнования формат по умолчанию, а у каждой дистанции может быть свой. Спека — [`docs/specs/per-distance-format.md`](../../specs/per-distance-format.md).

## Как пользоваться

### Android (Центр → создание или редактирование соревнования)

1. На первом шаге «Направление» — формат по умолчанию (подпись: «Можно изменить для отдельной дистанции»): «Заданное» или «По выбору». «Маркированная трасса» пока не поддержана и в Android не предлагается — ни у соревнования, ни у дистанции; в списке она видна, только если уже выбрана (соревнование или дистанция, созданные раньше).
2. В редакторе дистанции — поле **«Формат дистанции»**: «В заданном направлении», «По выбору — по баллам», «По выбору — по количеству КП». У новой дистанции подставлен формат соревнования (без отдельного пункта «Как у соревнования»). Если выбранный формат совпадает с форматом соревнования, дистанция сохраняется как «как у соревнования» и следует за ним при смене формата соревнования; другой формат сохраняется у дистанции явно. От выбора зависят баллы у КП и поле минимума КП. Если места на дистанции считаются иначе, чем в формате соревнования (по баллам вместо времени или наоборот), под полем — подсказка про политику КВ.
3. В редакторе группы поля штрафа за опоздание («Штраф за минуту», «Порог опоздания») видны, если **дистанция группы** — «по выбору» по баллам. При смене дистанции на такую пустые поля заполняются умолчаниями (1 и 30). Если у такой дистанции политика КВ «Штраф очками», а у соревнования КВ не задано, поле «Контрольное время (мин) *» у группы обязательно: без КВ штраф не начислится. При пустом поле «Сохранить группу» подсвечивает его ошибкой.
4. Блок «Контрольное время»: если есть и дистанции по времени, и дистанции с баллами, — два селектора: «При превышении КВ — дистанции по времени» и «При превышении КВ — дистанции с баллами». Если вид один — один селектор «При превышении КВ», как раньше. Селектор для дистанций с баллами виден и при пустом КВ соревнования (с подсказкой «Применяется к КВ групп…») — КВ на таких дистанциях часто задают только у групп; селектор для дистанций по времени — только при заданном КВ соревнования.
5. **Группы без нужного КВ** (дистанция с баллами, политика «Штраф очками», у соревнования и у группы КВ нет — например, после «Стандартных групп» или смены формата дистанции): в списке групп мастера метка «нужно КВ» и баннер, «Завершить» не проходит (сообщение со списком групп); в управлении соревнованием — такой же баннер.

### Web

- Мастер создания и вкладка «Общее» в управлении: те же поля «Направление» (с подсказкой про отдельные дистанции) и политики КВ по виду дистанции.
- Диалог дистанции в мастере и «+ Создать» на вкладке «Дистанции» — поле «Формат дистанции» с теми же тремя пунктами, что в Android; у новой дистанции подставлен формат соревнования, совпадающий с ним вариант сохраняется как «как у соревнования». В «Направлении» соревнования «Маркированная трасса» тоже скрыта (видна, только если уже выбрана).
- Вкладка «Дистанции» в управлении: у каждой дистанции кнопка **«Формат дистанции»** — для дистанций, импортированных из IOF XML (Mapper формат не передаёт), и для правки после создания. После сохранения сервер пересчитывает места групп этой дистанции.
- Карточка дистанции и строка дистанции в мастере показывают «Формат: …», если он отличается от формата соревнования.
- Сверка импорта результатов из HTML-протокола: колонка очков — у групп, чья дистанция «по выбору» по баллам.
- Диалоги группы (мастер и «Управление» → «Группы»): поле «Контрольное время, мин *» обязательно по тому же правилу, что в Android. Группы без нужного КВ: метка «нужно КВ» в списке мастера и в «Управление» → «Группы», баннер над вкладками управления (кнопка «К группам»), «Завершить» в мастере недоступна. Селектор политики для дистанций с баллами виден и без КВ соревнования.
- Публичная страница: на вкладке «Группы» при разных форматах у группы подписан формат её дистанции; на вкладке «Результаты» колонка очков, график и сортировка — по формату группы.

## Правила и граничные случаи

- **Эффективный формат группы** = формат её дистанции, иначе соревнования. Группа без дистанции (или с удалённой) — формат соревнования.
- «По выбору» у дистанции без своего режима берёт режим соревнования (в редакторе показывается явным вариантом).
- Проверка отметок при считывании чипа (Android) — по формату дистанции группы участника; карточка результата (баллы/время) — тоже. «Регистрация на финише» без группы — как раньше, только по финишу.
- Места: по баллам — только у дистанций «по выбору — по баллам», иначе по времени. Сервер (`ResultRanking`) и Android считают одинаково.
- Смена формата дистанции пересчитывает места её групп (сервер и локально на Android). Смена дистанции у группы на сервере тоже пересчитывает места группы.
- **Политика КВ** своя у двух видов дистанций:
  - по времени (заданное, маркированная, «по выбору» по количеству КП) — «Не учитывать» / «Дисквалифицировать», по умолчанию «Не учитывать»;
  - с баллами — плюс «Штраф очками», по умолчанию «Штраф очками». Штраф работает как раньше: после КВ группы — штраф за каждую минуту, после порога — результат обнуляется.
- Командный зачёт «по сумме времени» недоступен, если хотя бы одна дистанция (или формат по умолчанию) — «по выбору» по баллам.
- Импорт IOF XML: дистанции получают «как у соревнования»; предупреждение о несовпадении формата файла подсказывает, что формат можно задать отдельной дистанции.

## Как устроено

### Модель и API (eSport)

- `distances.direction`, `distances.by_choice_mode` — nullable, `null` = как у соревнования. В `DistanceRequest` значение `"INHERIT"` сбрасывает в `null`, а `null` значит «не менять» (старые клиенты поле не знают).
- `orienteering_competitions.time_overtime_policy`, `score_overtime_policy` — nullable (соревнования до фичи). Legacy `overtime_policy` всегда равна политике вида формата по умолчанию — её читают старые клиенты. Клиент без новых полей присылает только `overtimePolicy`: она обновляет политику вида формата по умолчанию, другая сохраняется.
- Разбор и умолчания — `domain/orienteering/CourseFormat.kt` (`effectiveCourseFormat`, `OvertimePolicies.resolve/legacy/forCourse`).
- `ResultRanking.recalculateGroup` берёт формат у дистанции группы; `DistanceService` пересчитывает группы при смене формата дистанции, `ParticipantGroupService` — при смене дистанции группы.
- Деталка события: у групп эффективные `direction` / `byChoiceMode`, у события — `isMixedFormat`, `timeOvertimePolicy`, `scoreOvertimePolicy`. Описание — `eSport/docs/API.md`.

### Android

- `:domain` `models/orienteering/CourseFormat.kt` — `CourseFormat`, `effectiveFormat`, `GroupFormats` (локальные группы), `remoteGroupFormats` (публичные экраны, ключ — серверный id группы), `overtimePolicyFor`, `legacyOvertimePolicy`, `resolveOvertimePolicies`.
- `Distance.direction` / `byChoiceMode`, `OrienteeringCompetition.timeOvertimePolicy` / `scoreOvertimePolicy`.
- Room `MIGRATION_61_62`: колонки формата у `distances`, `scoreOvertimePolicy` у соревнования; прежняя колонка `overtimePolicy` теперь хранит политику по времени (у score-О соревнований её значение переехало в `scoreOvertimePolicy`).
- `OrienteeringCompetitionInteractor.groupFormat`, `updateDistanceAndRanks`, пересчёт мест в `applyControlTimeToStoredResults` по формату группы.
- `OrientReadCardViewModel.courseFormat` — формат при считывании чипа.
- Мастер: `DistanceFormatOption.kt`, `DistanceEditor`, `ParticipantGroupCreator`, `ControlTimeBlock` (`CommonCompetitionFieldScreen`), `hasScoreCourses` / `hasTimeCourses` в `OrienteeringCreatorState`.
- Результаты/сплиты/графики/HTML-протокол (`feature:center`, `core:eventdetails`) — формат по группе.

### Web

- `src/lib/courseFormat.ts` — формат, варианты селектора, политики КВ, `groupDetailFormat`.
- `DistanceDialog`, `DistanceFormatDialog` (новый), `ControlTimeFields`, `CompetitionFormatFields`, `GroupDialog` / `AddGroupDialog` (штраф по дистанции группы), `DistancesTab`, `GroupsTab`, `ResultsTab`, `GroupSplitsTablePage`.

## Аналитика

| Событие | Параметры |
|---|---|
| `create_competition_finished` | + `mixed_format`: `true`, если хотя бы у одной дистанции формат отличается от формата соревнования (Android и web); `format` — формат по умолчанию |

## Ограничения и что не вошло

- Формат на уровне группы (разные правила на одной дистанции) — нужна отдельная дистанция.
- Mapper/IOF XML формат не передают; score-О по баллам КП в файле автоматически не определяется.
- Старые версии Android в соревновании с разными форматами проверяют чипы по формату соревнования — нужно обновить приложение. Механизма минимальной версии клиента пока нет.
- Экран деталей события на Android формат не показывает (как и раньше).
