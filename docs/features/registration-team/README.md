# Команда участника при регистрации на соревнование

## Зачем

При регистрации на соревнование участник указывает команду, за которую выступает. Подпись видна в стартовом протоколе и результатах. Если участник состоит в клубе Competra, его команда подставляется сама и привязывается к клубу; если нет — он пишет название свободным текстом. Поле необязательное.

## Как пользоваться

### Android

1. Откройте соревнование и нажмите **«Зарегистрироваться»** (на карточке события или на экране группы). Без входа в аккаунт приложение сначала отправит в профиль.
2. В шторке регистрации выберите группу.
3. Ниже — поле **«Клуб/команда (необязательно)»**:
   - если вы состоите в клубе, поле уже заполнено (правила подстановки — ниже). Под полем подпись **«Команда вашего клуба»** или **«Ваш клуб»**;
   - при вводе или нажатии на стрелку открывается список подсказок. Подпись под пунктом показывает, откуда он: **«Ваша команда»**, **«Ваш клуб»** или **«Уже есть в протоколе»**;
   - можно стереть поле или написать любое своё название.
4. Если введённое название совпадает с клубом, который есть в Competra и в котором вы не состоите, под полем появится карточка **«Клуб «…» есть в Competra»** (если клуб принимает заявки — с пометкой «можно подать заявку на вступление») и кнопка **«Открыть»**. Она закрывает шторку и открывает карточку клуба во вкладке «Клубы». Регистрация при этом не выполняется — к ней нужно вернуться.
5. Нажмите **«Готово»**.

### Web (competra.ru)

1. Войдите в аккаунт, откройте соревнование, вкладка **«Группы»**, кнопка регистрации на карточке нужной группы.
2. В диалоге регистрации — поле **«Клуб/команда (необязательно)»**. Поведение то же, что на Android: автоподстановка, выпадающий список с теми же подписями, подпись под полем для своей команды или клуба.
3. Карточка **«Клуб «…» есть в Competra»** со ссылкой **«Открыть»** ведёт на страницу клуба `/clubs/:id`.
4. Нажмите **«Зарегистрироваться»**.

## Что подставляется в поле

Подписи своих команд строятся как **«Клуб (Команда)»**, например «СК Азимут (Юниоры)». Если команда называется так же, как клуб, — только название клуба. Если вы в клубе, но ни в одной его команде по виду спорта соревнования, вариантом будет само название клуба.

Учитываются только команды того же вида спорта, что и соревнование (команда по лыжам не предлагается на старте по ориентированию).

При открытии регистрации поле заполняется по первому подходящему правилу:

1. команда или клуб, с которым вы регистрировались в прошлый раз;
2. ваша единственная команда;
3. ваш единственный клуб, если команд нет;
4. если вы не состоите ни в одном клубе — название, которое вы указывали в прошлый раз;
5. иначе (несколько команд, прошлого выбора нет) поле остаётся пустым, выберите из списка.

Порядок подсказок в списке: сначала свои команды и клубы, затем названия, которые уже указали другие участники этого соревнования (самые частые первыми). Список фильтруется по введённому тексту без учёта регистра.

## Правила и граничные случаи

- **Привязка к команде.** Участник привязывается к клубной команде, только если текст в поле в точности (без учёта регистра и лишних пробелов) совпадает с подписью вашей команды. Отредактировали подпись — остаётся просто текст без привязки.
- **Одинаковый текст — не одна команда.** Если двое написали «Лесные лисы», команда в системе не создаётся: у обоих просто одинаковая подпись в протоколе. Чтобы написание совпадало, второй участник увидит «Лесные лисы» в подсказках из протокола. Постоянную команду нужно создавать через клуб.
- **Нормализация.** Крайние и повторные пробелы убираются. Максимум 200 символов (на Android ввод обрезается, на web ограничен полем, сервер отвечает 422 на более длинное).
- **Нет сети или подсказки не загрузились.** Поле работает как обычное текстовое, регистрация не блокируется.
- **Начали печатать до загрузки подсказок.** Автоподстановка не перетирает введённое.
- **Вышли из команды, пока заполняли форму.** Сервер проверяет членство: если вас в команде уже нет, привязка отбрасывается, подпись сохраняется как текст.
- **Команду переименовали или удалили после регистрации.** Подпись в протоколе не меняется (это снимок на момент регистрации). При удалении команды привязка обнуляется.
- **Сменить команду после регистрации** нельзя: отмените регистрацию и зарегистрируйтесь заново, пока она открыта. После закрытия регистрации подпись меняет только организатор.

## Для организатора

- Организатор видит и редактирует подпись команды как раньше — свободным текстом в карточке участника (Android «Центр», web «Управление»). Подсказок по клубам там нет: чужие членства организатору не видны.
- Привязка участника к клубной команде сохраняется при правках и синхронизации, пока организатор не изменил подпись. Изменил (кроме регистра и пробелов) — привязка снимается.
- Участники, добавленные организатором вручную, к клубным командам не привязываются.

## Как устроено

### Данные

`orienteering_participants`:
- `command_name` — подпись для протокола (как и раньше);
- `team_id` — nullable, FK на `teams(id)` с `ON DELETE SET NULL`. Ставится только при самостоятельной регистрации.

### API (eSport, под JWT)

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/event/orienteering/competitions/{id}/registration-team-options` | `options` (свои команды по `kindOfSport` соревнования и клубы без команды, с готовой `label`), `protocolNames` (уникальные подписи протокола, до 50), `suggestedCommandName` |
| GET | `/api/clubs/match?name=` | Клубы с тем же названием (без учёта регистра; для «Клуб (Команда)» сравнивается и часть до скобки), где пользователь не состоит, до 3 |
| POST | `/api/event/orienteering/register` | Принимает `commandName` и необязательный `teamId` |

### eSport

- `src/main/kotlin/data/services/RegistrationTeam.kt` — чистые правила: нормализация, подпись «Клуб (Команда)», дедупликация протокола, выбор автоподстановки. Тесты — `src/test/kotlin/data/services/RegistrationTeamTest.kt`.
- `src/main/kotlin/data/services/RegistrationTeamService.kt`, `data/routing/RegistrationTeamRouting.kt` — эндпоинты подсказок и поиска клуба.
- `src/main/kotlin/data/services/OrienteeringParticipantService.kt` — проверки в `register`, сохранение `team_id` в `upsert`/`upsertAll`.
- Миграция колонки и FK — `src/main/kotlin/data/database/Databases.kt`.

### Android

- `domain/.../models/cyclic_event/RegistrationTeam.kt` — модели и правила клиента: `teamIdFor`, `teamSourceFor`, `suggestionsFor`. Тесты — `domain/src/test/.../cyclic_event/RegistrationTeamTest.kt`.
- `data/remote/.../CyclicEventDetailsRemoteDataSource.kt`, `CyclicEventDetailsRepositoryImpl.kt` — вызовы API.
- `core/eventdetails/.../presentation/registration/RegistrationTeamDelegate.kt` — загрузка подсказок, поиск клуба с задержкой 500 мс (от 2 символов, не для своей команды), состояние поля (`data/registration/RegistrationTeamState.kt`). Используется во ViewModel деталей события и экрана группы.
- `core/eventdetails/.../presentation/registration/RegistrationTeamField.kt` — поле с выпадающим списком и карточкой клуба.
- Переход в карточку клуба: `PendingTabNavigationRepository.set(TabRoutes.CLUBS, ClubDetailRoute)` + `switchTab` — экран клуба зарегистрирован только в графе вкладки «Клубы», `MainActivity` выполняет отложенный переход, когда вкладка становится активной.

### Web (`competra-web-ts`)

- `src/lib/registrationTeam.ts` — те же правила, что в Android domain.
- `src/features/competition-detail/RegistrationDialog.tsx` — поле-combobox и карточка клуба; `hooks.ts` — `useRegistrationTeamOptions`, `useClubMatches`.
- `src/api/competitionRepository.ts`, `src/api/clubRepository.ts` — вызовы API.

## Аналитика

| Событие | Когда | Параметры |

Одинаково на Android и web.

## Ограничения и что не вошло

- Смена команды после регистрации без её отмены.
- Командный зачёт и учёт `team_id` в рейтинге — данные копятся, но пока нигде не используются.
- Подсказки по клубам для организатора при ручном добавлении участника.
- Автосоздание команды из свободного текста — не планируется (см. «Одинаковый текст — не одна команда»).
