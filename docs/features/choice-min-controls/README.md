# «По выбору» с минимумом КП

## Зачем

Второй вариант формата «по выбору». Участник берёт КП в любом порядке, но не меньше заданного числа (например, 18 из 20) и обязательно все обязательные КП. Места распределяются по времени. Если КП взято меньше или пропущен обязательный, участник снимается. Первый вариант — score-О, где места считаются по сумме баллов, — работает как раньше.

## Как пользоваться

### Mapper

1. На вкладке **«Дистанции»** выберите тип **«Свободный порядок (минимум КП)»**.
2. В поле **«Минимум КП»** укажите, сколько КП нужно взять. «Все» — взять все КП дистанции.
3. Чтобы сделать КП обязательным, выберите его в списке «Пункты дистанции» и поставьте галочку **«Обязательный»**. Галочка есть и у дистанций с баллами.
4. Если правила у групп разные, сделайте отдельные дистанции из тех же КП. Например, детская дистанция — только из ближних КП, со своим минимумом.
5. Экспортируйте **«IOF XML…»** и загрузите файл в Competra («Импорт из Mapper»).

### Android (Центр)

1. **Создание соревнования → «Общее»**: «Направление» — **«По выбору»**, ниже **«Итог «по выбору»»** — **«По количеству КП»**. В «При превышении КВ» нет варианта «Штраф очками».
2. **Дистанция**: КП добавляются как обычно. Вместо баллов у КП — только переключатель **«Обязательный»**, под списком КП — поле **«Минимум КП»** (пусто — все КП). Если минимум больше числа КП, сохранить нельзя.
3. **Группа**: блока штрафа очками нет — только «Контрольное время».
4. **Считывание чипа**: вместо «БАЛЛЫ» — «ОБЩЕЕ ВРЕМЯ»; в таблице сплитов обязательные КП помечены «Обяз.», пропущенный обязательный КП — строкой «ПРОПУЩЕН». При недоборе — снятие с причиной «Взято 16 из 18 КП» или «Пропущен обязательный КП 31».
5. **Результаты** (Центр, детали события, онлайн-результаты, таблица сплитов группы, HTML-протокол): время вместо баллов, места по времени, отставание от лидера. Кнопки «График» нет — ни график очков, ни график отставания при свободном порядке не имеют смысла.

### Web (competra.ru)

1. **Создание соревнования → «Основное»** или **«Управление» → «Общее»**: «Направление» — **«По выбору»**, ниже **«Итог «по выбору»»** — **«По количеству КП»**. «Штраф очками» в «При превышении КВ» недоступен.
2. **Дистанция вручную** (шаг «Дистанции» мастера или «Управление» → «Дистанции» → «+ Создать»): КП через пробел, звёздочка после номера — обязательный КП (`31* 32 33`); поле **«Минимум КП»** (пусто — все). На шаге мастера под дистанцией видно «Взять 18 из 20 КП • обязательные: 31».
3. **Дистанции из файла**: «Загрузить IOF XML файл». Если в файле дистанции под другой формат (с баллами — в соревновании по количеству КП, с минимумом — в score-О, «по выбору» — в заданном направлении), под кнопкой появляется предупреждение; режим соревнования не меняется.
4. **Правила существующей дистанции** («Управление» → «Дистанции»): кнопка **«Минимум и обязательные КП»** (в score-О — **«Обязательные КП»**) — КП нажатием делаются обязательными, минимум вводится числом.
5. **Группы**: блока штрафа очками нет.
6. **Просмотр соревнования**: в карточке группы и дистанции — «Взять 18 из 20 КП» и «Обязательные КП: 31, 45»; в результатах нет колонки «Очки» и кнопки «График», в таблице сплитов под именем — время.

## Правила и граничные случаи

- **Минимум и обязательные КП** — свойство дистанции, а не группы. Группы с одинаковыми правилами ссылаются на одну дистанцию.
- **Обязательные КП входят в минимум.** Финишная станция в число взятых КП не входит.
- **Пустой минимум** (`null`) — взять нужно все КП дистанции.
- **Экспорт из Mapper.** Если минимум больше числа КП дистанции, Mapper отказывается экспортировать файл и называет дистанцию.
- **Старые версии клиентов.**
  - Не знают поля `minControlsCount` и при сохранении дистанции его не присылают. Сервер в этом случае значение не трогает.
  - Не знают и поля `byChoiceMode`. Для них соревнование выглядит обычным score-О с нулевыми баллами, а сортировка «баллы, затем время» сводится к сортировке по времени.
  - За недобор КП старые клиенты участника не снимут.

## Как устроено

### Данные (eSport)

- `orienteering_competitions.by_choice_mode` — `SCORE` (по умолчанию) или `MIN_CONTROLS`. Значим только для `direction = BY_CHOICE`.
- `distances.min_controls_count` — минимум КП; `null` — все КП.
- Обязательные КП — роль `"required"` в JSON `distances.control_points`. Эта роль уже была на Android, теперь её можно передать и через IOF XML.

### API

Новые поля, все необязательные:

| DTO | Поле | Семантика |
|---|---|---|
| `OrienteeringCompetitionRequest` | `byChoiceMode` | `SCORE` / `MIN_CONTROLS`; `null` — не менять, у нового соревнования — `SCORE` |
| `OrienteeringCompetitionResponse`, `CompetitionDetailResponse` | `byChoiceMode` | Текущий режим |
| `DistanceRequest` | `minControlsCount` | `N > 0` — минимум, `0` — все КП, `null` — не менять |
| `DistanceResponse` | `minControlsCount` | `null` — все КП |
| `ParticipantGroupDetailResponse` | `distanceMinControlsCount` | Минимум КП дистанции группы |

Места (`ResultRanking`): по сумме баллов только при `BY_CHOICE` + `SCORE` (функция `ranksByScore`), в остальных случаях — по `totalTime + penaltyTime`. Смена `byChoiceMode` пересчитывает места соревнования.

Умолчание политики КВ для нового соревнования: `SCORE_PENALTY` только у score-О, у `MIN_CONTROLS` — `IGNORE`.

Снятие за недобор КП и пропуск обязательного КП выставляет клиент при считывании чипа. Сервер этот статус не выводит, как и штраф очками в score-О.

### IOF XML (Mapper → eSport)

Правила, для которых в IOF 3.0 нет элементов, передаются в стандартных `<Extensions>`:

```xml
<CourseControl type="Control">
  <Control>31</Control>
  <Extensions><Required>true</Required></Extensions>
</CourseControl>
…
<Extensions><FreeOrder minControls="18"/></Extensions>   <!-- в <Course>; без minControls — все КП -->
```

### Android

- `domain/.../orienteering/ByChoiceMode.kt` — enum и `ranksByScore(direction, mode)`: единственная развилка «баллы или время». Проверки `== BY_CHOICE` в коде по-прежнему означают «свободный порядок» и общие для обоих режимов.
- `OrienteeringCompetition.byChoiceMode`, `Distance.minControlsCount`; Room — миграция 53→54 (`orienteering_competitions.byChoiceMode`, `distances.minControlsCount`).
- Синхронизация: Android всегда шлёт `minControlsCount` (`null` → `0`, «все КП»), чтобы сервер не принял его за «не менять».
- Проверка отметок — `computeMinControlsResult` в `feature/center/.../read_card/OrientReadCardViewModel.kt` (тесты — `ComputeMinControlsResultTest`). `totalScore` у результата остаётся `null`.
- Места — `recalculateRanksV2(results, direction, byChoiceMode)` в `OrienteeringCompetitionInteractor`; сортировка списков (`sortedForResults`) не менялась: при `totalScore = null` «баллы, затем время» сводится к времени.
- UI: `CommonCompetitionFieldScreen` (выбор режима, фильтр политики КВ), `DistanceEditor`, `ParticipantGroupCreator`, `OrientReadCardScreen`, экраны результатов в `feature/center` и `core/eventdetails`, `GroupSplitsTable` в `core/ui`.

## Ограничения и что не вошло

- На Android импорта XML нет — предупреждение о несовпадении формата есть только в вебе.
- Android: минимум КП группы не показывается участникам в деталях события (сервер его отдаёт в `distanceMinControlsCount`, веб — показывает).
- Web: полного редактирования существующей дистанции нет (как и раньше) — только правила «по выбору» и карта.
- Нет отметки финиша — время считается по последней засчитанной отметке, как и в score-О.
- Обязательные КП и минимум задаются на уровне дистанции; переопределения в группе нет. Разные правила — разные дистанции.
