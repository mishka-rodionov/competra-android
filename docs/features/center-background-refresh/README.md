# Фоновое обновление данных в «Центре»

## Зачем

На месте старта связь с сервером часто плохая. Раньше при входе в «Центр» и в управление соревнованием глобальный лоадер перекрывал всё приложение, пока не ответит сервер, — до минуты и дольше, хотя данные уже лежали в локальной БД. Организатор думал, что приложение зависло. Теперь экран сразу показывает сохранённые данные, а свежие с сервера подтягивает в фоне, ничего не блокируя.

## Как пользоваться

### Android

**«Центр» → список «Мои старты»** и **экран управления соревнованием**:

- При открытии данные из телефона видны сразу. Под заголовком — тонкая полоса прогресса и строка «Обновляем данные…», пока идёт загрузка с сервера.
- После загрузки — «Обновлено в 12:34».
- Если сервер не ответил — серая иконка облака и «Офлайн · данные от 12:34» (если в этот раз обновить ещё не удалось — «Офлайн · данные из телефона»). Это не ошибка: в офлайне можно полноценно работать, изменения уйдут на сервер при появлении сети. Поэтому статус намеренно спокойный — без красного цвета и без кнопки «Повторить».
- Потянуть экран вниз (pull-to-refresh) — обновить данные вручную. Тонкая полоса прогресса видна и при обновлении жестом, вместе с его индикатором.

На новом устройстве (в телефоне ещё нет соревнований) вместо «У вас пока нет созданных событий» во время первой загрузки показывается «Загружаем ваши события…» с индикатором — внутри списка, а не на всё приложение. Если первая загрузка не удалась, — «Не удалось загрузить события с сервера. Они появятся, когда будет связь…»: события на сервере могут быть, поэтому «нет событий» не пишем.

### Web

Не менялось: веб-клиент на TanStack Query и так показывает закэшированные данные и обновляет их в фоне.

## Правила и граничные случаи

- **Когда обновляется автоматически:** при каждом показе экрана (вход на вкладку, возврат с другого экрана или из фона), но не чаще раза в 30 секунд; если прошлая попытка не удалась — сразу. Ещё — при появлении сети в телефоне, если экран открыт.
- **Таймаут:** одна фоновая загрузка ограничена 45 секундами, после этого — статус «Офлайн». Обновление жестом запускается без ограничения частоты; если загрузка уже идёт, второй не будет.
- **Ошибки:** фоновая загрузка не показывает глобальный диалог сетевой ошибки — только строку статуса.
- **Соревнование ещё не на сервере** (создано без сети и не выгружено): в управлении тянуть с сервера нечего, строка статуса не показывается.
- **Локальные несинхронизированные правки не затираются:** серверная версия соревнования применяется только к записям без неотправленных изменений (правила `planServerMerge`, как для дистанций, групп и участников). Записи с правками выгрузит синхронизация, конфликт решит сервер (409).
- **Слияние списка с сервером безопасно для гонок с синхронизацией:** выполняется в одной транзакции Room (правка или пометка на удаление из UI не вклинится между чтением и записью, список перерисуется один раз); серверная версия старше локальной (`serverUpdatedAt`) не применяется — ответ на запрос, ушедший до выгрузки локальной правки, её не затрёт; соревнование, физически удалённое после удаления на сервере, не вставляется обратно запоздавшим ответом.
- **Смена аккаунта:** статус и троттлинг прошлого пользователя сбрасываются, список нового загружается сразу.
- **Экран управления:** чтение из БД при показе экрана и перечитывание после ответа сервера идут строго по очереди — данные не применятся в обратном порядке.
- **Изменения с сервера теперь доходят до списка:** раньше список только добавлял новые соревнования, а уже известные (например, изменённые в вебе) не обновлял.
- **Удаление соревнования** — локальная пометка, без лоадера; список обновляется сам.

## Как устроено

**Android** (`competra-android/`):

- `feature/center/.../data/refresh/BackgroundRefresher.kt` — общий помощник: одна загрузка за раз, `reset()` при смене аккаунта, таймаут `BACKGROUND_REFRESH_TIMEOUT_MS` (45 с), троттлинг автообновлений `AUTO_REFRESH_MIN_INTERVAL_MS` (30 с), состояние `RemoteRefreshState` (`isRefreshing`, `isPullRefresh`, `lastUpdatedAt`, `isFailed`).
- `feature/center/.../presentation/common/RefreshStatusBar.kt` — строка статуса: полоса прогресса, время обновления, офлайн-статус с иконкой `ic_cloud_off_24px` (`core/resources`).
- `feature/center/.../presentation/main/CenterViewModel.kt` — список из потока Room (`observeCompetitionsByUserId`), фоновое обновление через `OrienteeringCompetitionInteractor.refreshCompetitionsFromServer`; `onResume()` вызывается из `LifecycleEventEffect(ON_RESUME)` в `CenterScreen.kt`. `PullToRefreshBox` вокруг списка.
- `feature/center/.../presentation/event_control/orienteering/OrienteeringEventControlViewModel.kt` — `loadLocalCompetitionData` (только БД, под `Mutex`) сразу при показе экрана, `refreshFromServer` (дистанции, группы, участники, заявки на привязку) — в фоне, после него экран перечитывается из БД. `fetchAndSyncFromServer` / `fetchAndSyncParticipantsFromServer` возвращают `Boolean` — ответил ли сервер.
- `data/local/.../OrienteeringCompetitionDao.kt` — `observeCompetitionsByUserId` (Flow), `getCompetitionsByUserIdIncludingDeleted`.
- `data/local/.../OrienteeringCompetitionLocalRepositoryImpl.kt` — `mergeCompetitionsFromServer`: в `withTransaction`, `planServerMerge` по `competitionId`, пропуск серверных версий старше локальной, обновление через `updateCompetition(markUnsynced = false)` (UPDATE, без каскада; сохраняет локальные флаг жеребьёвки и время старта); `purgedCompetitionIds` — физически удалённые за жизнь процесса, не вставляются повторно.
- `domain/.../repository/NetworkAvailabilityRepository.kt` — поток событий «появилась сеть»; источник — `NetworkAvailabilityObserver` в `CompetraApp`.

Бэкенд и API не менялись: используются те же `GET`-запросы, что и раньше.

## Аналитика

Отдельного события нет — служебное действие без бизнес-эффекта, как и pull-to-refresh в [events-list-refresh](../events-list-refresh/README.md).

## Ограничения и что не вошло

- Соревнование, удалённое на сервере (например, из веба), из списка в телефоне не удаляется: каскадное удаление унесло бы участников и результаты, которые могут быть ещё не выгружены.
- Остальные экраны «Центра» (стартовый протокол, жеребьёвка, стартовая решётка) и действия (старт, завершение) по-прежнему используют глобальный лоадер.
