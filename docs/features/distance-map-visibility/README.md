# Карта дистанции до старта

## Зачем

Карту дистанции и координаты КП нельзя показывать участникам до старта — иначе дистанцию можно изучить заранее. Раньше бэкенд отдавал их любому, кто открыл страницу соревнования, поэтому организаторам приходилось прикреплять карты только после окончания. Теперь карту можно прикрепить заранее: до старта её видят только организаторы, остальные — с момента старта.

## Как пользоваться

### Web

1. Организатор: «Управление» → соревнование → «Дистанции» → «Прикрепить карту» — как раньше, в любой момент. Организатор видит «Открыть карту дистанции» и на публичной странице соревнования.
2. Участник или зритель до старта: на странице соревнования, вкладка «Дистанции», у дистанции с картой вместо кнопки — надпись «Карта дистанции откроется после старта».
3. После старта у всех появляется «Открыть карту дистанции», а на «Онлайн-треках» — карта-подложка.

### Android

Карта дистанции показывается только на экране онлайн-треков, который открывается после старта, — для пользователя ничего не изменилось.

## Правила и граничные случаи

- **Кто видит всегда:** владелец соревнования, FOUNDER/ADMIN клуба-организатора и любой организатор из списка организаторов, с любой ролью (включая «Другое»). Это шире, чем право редактировать дистанции: редактор, получивший урезанную дистанцию, затёр бы данные при сохранении.
- **Когда открывается остальным:** сохранённый статус `IN_PROGRESS`/`FINISHED`/`ARCHIVED` либо наступило время старта (`startTime`) — не дожидаясь, пока шедулер обновит статус. Черновик (`DRAFT`) не открывается никогда.
- **Что скрыто до старта:** `mapUrl`, углы карты, координаты КП, старта и финиша. Название, длина, набор, число КП, номера, роли и очки КП видны: они нужны для правил «по выбору».
- **Раздельный старт:** карта открывается со старта соревнования (первой минуты), а не участника. Поздние стартующие формально могут её открыть — осознанный компромисс ради онлайн-треков с подложкой.
- **Онлайн-треки до старта:** бегун может включить трек за сутки до старта. Кнопку/вкладку «Онлайн-треки» до старта видит только организатор — проверить работу трекинга (на его экране есть и карта, и КП). Остальным она появляется со стартом. Подробнее — [live-track-viewer](../live-track-viewer/README.md).
- **Просроченный токен** на публичной ручке не даёт 401: пользователь считается анонимом и получает данные без карты.
- **Замена карты:** старый файл удаляется из хранилища, если на него не ссылается другая дистанция. Ошибка удаления не мешает сохранению — пишется в лог.
- **Сохранение без координат КП:** если в запросе у КП нет координат, сервер оставляет сохранённые для КП с тем же номером — как и для старта/финиша, `null` значит «не трогать».

## Для организатора

Карты можно прикреплять заранее: участники увидят их только после старта. Карты, прикреплённые до этого изменения, могли успеть утечь по прямой ссылке — чтобы закрыть такую карту, прикрепите её заново («Заменить карту»): файл получит новый адрес, а старый удалится.

## Как устроено

**API.** `GET /api/event/orienteering/distances?competitionId=…` остаётся публичным, но читает необязательный Bearer-токен. Не-организатору до старта поля карты и координат приходят `null`. Новое поле `hasMap: Boolean` — прикреплена ли карта (отдаётся всегда). `GET /api/event/orienteering/competitions/public/{id}` тоже читает токен и отдаёт `viewerIsOrganizer` — по нему клиенты показывают организатору онлайн-треки до старта.

**eSport** (`competra-server/eSport/`):
- `src/main/kotlin/Authentication.kt` — `ApplicationCall.optionalUserId()`: userId из токена без 401 на невалидный.
- `src/main/kotlin/data/services/CompetitionStatus.kt` — общие `computeEffectiveStatus` и `isCompetitionStarted` (раньше дублировались в сервисах соревнований и участников).
- `src/main/kotlin/data/services/CompetitionAuthorization.kt` — `isCompetitionOrganizer`.
- `src/main/kotlin/data/services/DistanceService.kt` — `getByCompetition(competitionId, viewerUserId)` + `withoutCourse()`; в `upsertAll` — `keepStoredCoordinates` и удаление заменённой карты.
- `src/main/kotlin/data/services/UploadService.kt` — `deleteDistanceMap(url)` (только ключи `distance-map/` своего бакета).
- `src/main/kotlin/data/response/orienteering/DistanceResponse.kt` — `hasMap`.
- `src/main/kotlin/data/services/OrienteeringCompetitionService.kt` (`getById`) + `CompetitionDetailResponse.kt` — `viewerIsOrganizer` по токену (query-параметру `userId` не доверяем).

**Web** (`competra-web-ts/`):
- `src/types/distance.ts` — `hasMap?`.
- `src/features/competition-detail/DistancesTab.tsx` — надпись «Карта дистанции откроется после старта».
- `src/pages/CompetitionDetailPage.tsx` — условие вкладки «Онлайн-треки» (`STARTED_STATUSES` в `features/competition-detail/hooks.ts`); `getCompetitionDetail` в `src/api/competitionRepository.ts` ходит через `authRequest`, чтобы бэкенд видел токен.

**Android** (`competra-android/`):
- `data/remote/.../response/events/CompetitionDetailResponse.kt` — `viewerIsOrganizer`; `CyclicEventDetailsRepositoryImpl.kt` — `hasStarted` из серверного статуса (ARCHIVED в `EventStatus` не различается).
- `domain/.../cyclic_event/CyclicEventDetails.kt` — `hasStarted`, `viewerIsOrganizer`.
- `core/eventdetails/.../data/details/EventDetailsState.kt` — `isLiveTracksButtonVisible`.
- `hasMap` в DTO дистанции не добавлен — Gson его игнорирует.

## Ограничения и что не вошло

- Файл карты по-прежнему лежит в Object Storage с публичным чтением по UUID-ссылке: кто получил ссылку (организатор), сохранит доступ. Приватный бакет и presigned-ссылки с TTL — отложены.
- Дистанция организатора, сохранённая в Android до старта, не урезается — организатор видит всё.
- Новых событий аналитики нет.
