# Мастер создания соревнования

## Зачем

Организатор создаёт соревнование ориентирования в пять шагов: «Основное» → «Регистрация» → «Организатор» → «Дистанции» → «Группы». Мастер должен проходиться быстро и не оставлять за собой битых данных: дублей соревнования, координат «0, 0». Группы без дистанции допустимы — см. [groups-without-distance](../groups-without-distance/README.md). Здесь описаны общие правила мастера и средства, которые ускоряют заполнение: импорт дистанций из Mapper, стандартные группы, подстановка из профиля.

## Как пользоваться

**Android**: Центр → «Создать» → «Спортивное ориентирование». Тот же мастер открывается при редактировании соревнования.
**Web**: «Управление» → «Создать соревнование» (`/management/create`). Существующее соревнование правится на вкладках страницы управления; дистанцию там можно удалить кнопкой «Удалить дистанцию» на её карточке во вкладке «Дистанции» (с подтверждением).

1. **Основное** — название, обложка (кроп 16:9), дата и время старта, часовой пояс, место проведения, точка старта на карте, формат, отметка, способ старта, КВ, командный зачёт, описание. Если время старта уже прошло, мастер предупреждает: регистрация сразу закроется. В Android новое соревнование по умолчанию стартует завтра в 10:00.
2. **Регистрация** — открыть сразу или с даты; окончание — в момент старта или за сутки; взнос и валюта (RUB, BYN, KZT, USD, EUR).
3. **Организатор** — «Организатор (ФИО)», телефон, email, клуб-организатор (если вы FOUNDER/ADMIN клуба), ссылки: сайт, положение, карта. ФИО, телефон и email подставляются из профиля.
4. **Дистанции** — вручную или «Импорт из Mapper (IOF XML)». Каждую добавленную дистанцию можно изменить или удалить. Шаг можно пропустить, если дистанции ещё не спланированы.
5. **Группы** — вручную или **«Стандартные группы»**: отметить М10…М65, Ж10…Ж65, Open и дистанцию по умолчанию. Каждую группу можно изменить или удалить.

## Правила и граничные случаи

- **Обязательные поля**, одинаковые на обеих платформах:
  - название, дата, адрес — в вебе для прошедшего соревнования адрес не обязателен;
  - телефон — в вебе для прошедшего соревнования не обязателен;
  - хотя бы одна группа (дистанции необязательны: у группы дистанция может быть «Не назначена»);
  - дата начала регистрации, если она открывается не сразу.
- **Регистрация не может открыться позже старта** — «Далее» на шаге 2 не пускает дальше.
- **Пол и возраст по названию группы** (и в «Стандартных группах», и при вводе названия вручную). Возраст считается как год соревнования минус год рождения.
  - меньше 21 → «до N лет» (`maxAge`), больше 21 → «N лет и старше» (`minAge`), 21 → без ограничения;
  - «М»/«M» → мужчины, «Ж»/«W»/«F» → женщины, «МЖ» → без ограничения по полу;
  - поле, которое организатор поменял сам, при дальнейшем вводе названия не перетирается;
  - при правке существующей группы автозаполнение не работает.
- **Дистанция для стандартной группы** подбирается по совпадению названий без учёта регистра, пробелов и раскладки М/M, Ж/W («M 21» ↔ «М21»). Если совпадения нет — берётся выбранная в диалоге. Группы с уже существующими названиями не добавляются.
- **Удаление**:
  - дистанцию, на которую ссылаются группы, удалить нельзя — появляется сообщение со списком групп. В вебе это правило действует и в мастере, и на вкладке «Дистанции» страницы управления. Сервер (`DELETE /event/orienteering/distances/{id}`) его не проверяет — проверка только в клиентах;
  - в Android нельзя удалить группу, в которой уже есть участники;
  - в вебе нельзя убрать XML-файл, пока его дистанции выбраны в группах.
- **Координаты старта**: если точка не выбрана, в Android показывается «Не выбрано», а на сервер уходит `null`, а не «0, 0».
- **Повтор публикации в вебе**: соревнование получает id один раз на весь мастер. Если «Завершить» упало на дистанциях или группах, повторное нажатие:
  - обновляет то же соревнование (upsert);
  - отправляет уже сохранённые дистанции с их серверными id;
  - удаляет на сервере дистанции, убранные из мастера после ошибки;
  - не импортирует тот же XML второй раз, а другой файл заменяет ранее импортированные дистанции.
- **Импорт XML в Android** разбирает файл локально и работает офлайн. Дистанция с тем же названием обновляется, а не дублируется; её описание и введённое вручную стартовое КП сохраняются. Повреждённый файл или файл без `<Course>` дают сообщение, мастер не падает.

## Для организатора

Название дистанций в Mapper так же, как групп («М21», «Ж14»): тогда «Стандартные группы» сами подберут каждой группе её дистанцию. Инструкции на сайте:
- `competra-web-ts/public/guides/first-competition-guide.html` — мастер;
- `competra-web-ts/public/guides/mapper-course-planning-guide.html` — импорт.

## Как устроено

**Android** (`competra-android`):
- `domain/.../models/orienteering/IofCourseXmlParser.kt` — локальный разбор IOF XML 3.0, порт `IOFXmlParser.kt` из eSport. Меняешь один парсер — поправь и другой.
- `domain/.../models/orienteering/StandardGroups.kt`:
  - `TITLES` — список стандартных групп;
  - `parseTitle` — пол и возраст по названию;
  - `matchDistance` — дистанция по совпадению названий.
- `feature/center/.../orientiring_competition_create/`:
  - `OrienteeringCreatorViewModel` — действия `DeleteDistance`, `DeleteGroup`, `ImportCoursesXml`, `AddStandardGroups`, `prefillFromProfile`;
  - `StandardGroupsDialog.kt` — диалог стандартных групп;
  - сообщения мастера выводятся снекбаром (`state.message`, `rememberWizardSnackbar`).
- `OrienteeringCompetitionInteractor.deleteDistance/deleteParticipantGroup`:
  - ни разу не выгруженная запись удаляется локально;
  - выгруженная помечается `isDeleted`, и `SyncOrchestrator` отправляет DELETE.
- `Competition.organizerName` — новое поле, Room-миграция 57→58.

**Web** (`competra-web-ts`):
- `src/pages/CreateCompetitionPage.tsx` — стабильный `competitionId` и `PublishProgress` (повтор без дублей).
- `PendingDistance.key` / `PendingGroup.distanceKey` — группа ссылается на дистанцию по ключу, а не по позиции в списке, поэтому удаление и правка дистанций не сдвигают выбор групп.
- `src/features/management/`:
  - `CreateCompetitionSteps.tsx`, `createCompetitionValidation.ts`;
  - `StandardGroupsDialog.tsx`, `CoverPickerField.tsx`;
  - `DistanceDialog`/`GroupDialog` — проп `initial` для правки;
  - `LimitAndFeeFields` — валюта.
- `src/lib/standardGroups.ts` — те же правила, что в Android.
- `src/features/competition-detail/DistancesTab.tsx` — удаление дистанции у существующего соревнования (только в режиме организатора, `showImport`): проверка групп через `useGroups`, диалог подтверждения, `distanceRepository.deleteDistance`.
- `src/lib/controlPoints.ts` → `formatControlPoints`.
- `EditCompetitionTab` и `competitionToFields` передают `organizingClubId` и рамку кропа обложки. Сервер перезаписывает их при каждом upsert, поэтому раньше правка на сайте их стирала.

**eSport**:
- `CompetitionResponse` (`GET /event/orienteering/competitions`) теперь отдаёт `organizerName`. Без него Android не знал ФИО организатора и стирал его при каждом сохранении, а веб-вкладка «Общее» показывала пустое поле.

## Ограничения и что не вошло

- **Черновика нет.** Android сохраняет статус `DRAFT`, но eSport (`computeEffectiveStatus`) показывает его как открытую регистрацию. Кнопку «Опубликовать» нужно спроектировать отдельно.
- **Удаление в Android до синхронизации.** Удалённая в мастере выгруженная дистанция или группа видна на других экранах, пока синхронизация не отправит DELETE.
- **Нет связи групп с дистанциями из XML.** Mapper не экспортирует `ClassCourseAssignment`, поэтому группы по-прежнему создаются отдельно.
- **Веб-черновик не сохраняется** при перезагрузке страницы.
