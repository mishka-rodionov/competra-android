# Регистрация на финише

## Зачем

«Технический старт»: соревнование проводят без заранее зарегистрированных участников. Люди приходят на старт, получают чипы, стартуют по стартовой станции и бегут. На финише организатор считывает чип и только тогда вносит человека и его группу. Правильность прохождения организатор оценивает сам, места по группам считаются автоматически.

Аналог в SportOrg — настройка «Привязка чипа при считывании» и флаг группы «Любая дистанция». Дизайн — [spec](../../specs/finish-registration.md).

## Как пользоваться

### Создание (Android и web)

- **Android**: мастер создания → шаг «Основное» → переключатель **«Регистрация на финише»**. При включении способ старта фиксируется: «По стартовой станции», а система отметки — Sportiduino.
- **Web**: «Управление» → «Создать» → шаг «Основное» → галочка **«Регистрация на финише»** (в «Добавить прошедшее» её нет). При включении вместо выбора способа старта — подсказка «Старт — по стартовой станции».
- **Web, редактирование** («Управление» → соревнование → «Общее»): режим только показывается, способ старта не меняется.
- **Web, детали соревнования**: в карточке «Когда и где» — «Регистрация: На финише — организатор вносит участников при считывании чипа».
- В форме дистанции (Android и web) пустые поля финиша и старта заполняются кодами 245 и 240 (Sportiduino).
- Группы создаются как обычно (хотя бы одна обязательна). Дистанции необязательны.
- Режим задаётся в мастере. На экране управления соревнованием видна подпись «Регистрация на финише — участников вносите при считывании чипа».
- На экране управления (Android) «Стартовый протокол» называется **«Участники»**: там внесённых на финише можно поправить (ФИО, группа). **«Выдача чипов»** необязательна: в ней можно заранее записать чип заявленным онлайн или внесённым организатором участникам; не записанный на старте чип привязывается на финише (вкладка «Уже заявлен»). Заявленные без чипа не блокируют «Открыть старт».
- Группы можно добавлять и после открытия старта (редактирование соревнования → «Группы» или «+ новая группа» в карточке участника) — статус соревнования и секундомер при этом сохраняются.

### На финише (только Android)

1. Центр → соревнование → «Сканировать», приложить чип.
2. **Чип уже есть у участника** — всё как обычно: результат считается, при повторном считывании показывается конфликт.
3. **Чип незнакомый** — считывание сохраняется в очередь «неразобранных» и сразу открывается карточка участника (это нормальный сценарий режима, красного сообщения об ошибке нет):
   - Вверху — **отметки на чипе**: цепочка КП по времени («240 (старт) → 46 → 47 → 48 → 245 (финиш)»), время старта и время на дистанции. Пустой чип — предупреждение «На чипе нет отметок».
   - **«Новый участник»**: Фамилия, Имя (с подсказками по прошлым соревнованиям организатора), Группа (список + «+ новая группа»), Команда (необязательно) → «Сохранить и посчитать результат».
   - **Подсказка группы по отметкам**: группа, у дистанции которой взяты все КП, помечается «· по отметкам», под списком — «По отметкам подходит: …». Если подходит одна группа, она выбирается сразу. Порядок КП не учитывается; из нескольких подходящих остаются группы с самой длинной дистанцией. Группы без дистанции не подсказываются.
   - **«Уже заявлен»** (вкладка видна, если есть участники без результата, в том числе со сброшенным — «зарегистрирован»): поиск по ФИО/номеру, касание — чип привязывается к этому участнику.
4. Карточку можно закрыть: считывание остаётся в очереди, на экране — плашка **«Неразобранные считывания: N»** (нейтрального цвета, не красная) → «Разобрать» открывает список (номер чипа, время считывания, число отметок, время от стартовой до финишной станции). В строке также цепочка КП и подходящие по отметкам группы. Касание строки — та же карточка; «Удалить» — убрать ошибочное считывание.
5. В управлении соревнованием при неразобранных считываниях видна строка «Неразобранные считывания: N» — открывает экран считывания.

### Исправление участника на экране считывания (только в этом режиме)

Под карточкой участника — две кнопки:

- **«Изменить участника»** — ФИО, команда, группа (с подсказкой по отметкам и «+ новая группа»). При смене группы результат пересчитывается по дистанции новой группы из исходного считывания чипа и сразу заменяет сохранённый (при любом статусе, в том числе DSQ: старый результат относится к прежней группе). Места пересчитываются в обеих группах. Если сохранённого результата ещё не было, DSQ по-прежнему ждёт «Сохранить результат».
- **«Отвязать чип»** — считывание возвращается в «Неразобранные», и сразу открывается его карточка. В подтверждении два варианта:
  - **«Удалить участника»** — внесён по ошибке: участник и его результат удаляются (после старта это разрешено только в этом режиме, в том числе на сервере);
  - **«Оставить участника»** — заявлен, но чип считан не ему: чип снимается, результат сбрасывается в «зарегистрирован», участник снова доступен во вкладке «Уже заявлен».

В «Участниках» (бывший «Стартовый протокол») группу можно сменить в диалоге редактирования, пока у участника нет результата. С результатом диалог подсказывает менять группу на экране считывания: там есть отметки чипа для пересчёта.

Если результат «зарегистрирован» (чип отвязали), новое считывание записывается поверх без диалога конфликта.

### Ручной статус (только в этом режиме)

Под результатом на экране считывания:

- **«Снять результат»** — у засчитанного результата → DSQ.
- **«Засчитать результат»** — у снятого, если есть время старта и отметка финишной станции: время = финиш − старт.
- **«Засчитать финиш по времени считывания»** — если отметки финиша нет: добавляется отметка финишной станции во время считывания чипа, результат пересчитывается, организатор сохраняет его кнопкой «Сохранить результат».

Ручной статус помечается подписью «Статус выставлен организатором вручную».

## Правила и граничные случаи

- **Старт**: отметка стартовой станции. Нет отметки — DSQ «Нет отметки на стартовой станции».
- **Коды станций по умолчанию** (для всех соревнований, не только этого режима): если у дистанции не задан стартовый/финишный КП или у группы нет дистанции, берутся стандартные коды системы отметки — Sportiduino: старт **240**, финиш **245**. В форме дистанции эти коды подставляются в пустые поля.
- **Группа без дистанции**: КП не проверяются, статус «финишировал», время = первая отметка финиша после старта − старт. Нет отметки финиша — DSQ «Нет отметки финиша». Вне этого режима группа без дистанции по-прежнему не считается (см. [groups-without-distance](../groups-without-distance/README.md)).
- **Группа с дистанцией**: обычная проверка по формату соревнования и КВ.
- **Ручной статус не перетирается** пересчётом контрольного времени (локально и на сервере). Повторное считывание чипа даёт обычный конфликт: применив новый результат, организатор возвращает автоматический статус.
- **Номер участника** — следующий после максимального по соревнованию; время старта — 0 до разбора отметки стартовой станции.
- **Очередь хранится только на телефоне** (Room) и на сервер не уходит; при смене телефона неразобранные считывания пропадут. Созданные участники и результаты синхронизируются как обычно.
- **Завершение соревнования** при неразобранных считываниях: в подтверждении «Осталось неразобранных считываний: N — они не попадут в результаты», кнопки «Разобрать» / «Всё равно завершить».
- Баннер «Все участники финишировали» и предупреждение о группах без дистанции в этом режиме не показываются.
- После завершения соревнования незнакомый чип не ставится в очередь (режим только просмотра).

## Как устроено

**Модель**

- `OrienteeringCompetition.isFinishRegistration` — флаг соревнования.
- `OrienteeringResult.isStatusManual`, `OrienteeringResult.readAt` — ручной статус и время считывания чипа.
- `PunchingSystem.defaultStartStationCode` / `defaultFinishStationCode` — коды станций по умолчанию (при добавлении новой системы отметки задать их).
- `UnassignedChipRead` — неразобранное считывание (`competitionId`, `chipNumber`, `readAt`, `clearTime`, `splits`), только локально.

**API (eSport)** — `competra-server/eSport/docs/API.md`:

- `isFinishRegistration` в `OrienteeringCompetitionRequest/Response` и `CompetitionDetailResponse`; `null` в запросе — не менять.
- `isStatusManual`, `readAt` в `OrienteeringResultRequest/Response`; `null` в запросе — не менять.
- `ResultRanking.recalculateGroup` не переводит в OVERTIME результаты с `isStatusManual`.
- `DELETE /participants/{id}` после старта разрешён только в этом режиме: участник удаляется вместе со своими результатами, места в группах пересчитываются (`OrienteeringParticipantService.deleteById`).
- Колонки: `orienteering_competitions.is_finish_registration`, `orienteering_results.is_status_manual`, `orienteering_results.read_at` (миграции в `Databases.kt`).

**Web** (`competra-web-ts`):

- `src/features/management/dictionaries.ts` — `finishRegistrationPatch`, `DEFAULT_STATION_CODES`; `CreateCompetitionSteps.tsx` — галочка; `EditCompetitionTab.tsx` — подпись вместо выбора старта; `DistanceDialog.tsx` — коды по умолчанию; `competition-detail/InfoTab.tsx` — подпись режима.
- `public/guides/first-competition-guide.html` — упоминание режима и кодов станций.

**Android** (`competra-android`):

- `data/local/...`: `UnassignedChipReadEntity`, `UnassignedChipReadDao`, `UnassignedChipReadRepositoryImpl`, миграция `MIGRATION_59_60`.

## Ограничения и что не вошло

- Пол и год рождения участника в карточке не вводятся — у участника соревнования нет таких полей.
- Общий старт по секундомеру, повторная выдача чипов одного номера.
- Автоматическая настройка «без отметки финиша — по времени считывания».
- Ручные статусы в обычных соревнованиях и на экране результатов (сейчас — только на экране считывания).
- Смена группы участника с результатом в списке «Участники» (только на экране считывания — там есть отметки чипа).
- Разбор считываний в вебе; синхронизация очереди между устройствами.
- Коды станций по умолчанию для SPORTIDENT и SFR.
