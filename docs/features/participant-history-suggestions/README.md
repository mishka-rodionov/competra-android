# Подсказки участников из прошлых соревнований

## Зачем

Организатор часто вносит в протокол одних и тех же людей: клубные старты, серии, постоянные участники. Раньше имя, фамилию и команду приходилось набирать каждый раз заново. Теперь в диалоге «Новый участник» есть подсказки из прошлых соревнований этого организатора: две-три буквы, тап по подсказке, «Добавить участника».

## Как пользоваться

**Android** (Центр → соревнование → «Стартовый протокол»):

1. В группе нажать «Добавить» — откроется диалог «Новый участник». Поля: «Фамилия» (фокус сразу на ней), «Имя», «Команда (необязательно)».
2. Начать вводить фамилию или имя (в любое поле). С двух букв под полем «Имя» появляется блок «Участвовали раньше» — до 5 человек: «Фамилия Имя» и строка «Команда · Группа · дата последнего соревнования».
3. Тап по подсказке заполняет фамилию, имя и команду. Стартовое время дозаявки (если жеребьёвка проведена) выбирается как обычно.
4. «Добавить участника». Диалог остаётся открытым для следующего, как и раньше.

Поиск — по началу слов, регистр и «ё/е» не важны; можно ввести начало и фамилии, и имени («ив пе» найдёт «Иванов Пётр»).

**Массовое добавление.** В диалоге «Новый участник» под строкой «Группа: …» — кнопка «Выбрать из прошлых соревнований» (видна, когда в истории есть кто-то, кого ещё нет в протоколе). Она открывает поверх формы экран «Из прошлых соревнований» на весь экран. Под заголовком — «Добавление участников в группу: <группа>». Свайпом вниз экран не закрывается — выйти можно кнопкой «Назад» справа от заголовка (или системной кнопкой «назад»); вернётесь к форме одного участника:

1. Сверху поиск «Поиск по фамилии или имени» — пустой показывает всю историю, иначе те же правила, что у подсказок, но без ограничения в 5 человек.
2. Порядок: сначала те, чья последняя группа совпадает с группой, в которую добавляют (при добавлении в М21 — бегавшие в М21 в прошлый раз), дальше остальные; внутри — как у подсказок (частые, затем недавние). Группы сравниваются без регистра и пробелов, латинская «M» равна кириллической «М».
3. Строки с галочками: «Фамилия Имя» и «Команда · Группа · дата». Тап по строке или галочке отмечает человека; отметки сохраняются при смене поиска. Над кнопкой — «Отмечено: N» (отмеченные могут быть скрыты поиском) или «Отметьте участников».
4. Если жеребьёвка уже проведена — «Стартовое время»: «Свободные минуты» или «В конец протокола» (ввести время вручную для пачки нельзя).
5. «Добавить в группу <группа>» (неактивна, пока никто не отмечен) — все отмеченные добавляются в группу, для которой открыт диалог, с командой из последнего участия; экран выбора и диалог «Новый участник» закрываются.

**«Очистить»** — кнопка справа от заголовка «Новый участник»: стирает фамилию, имя, команду и введённое вручную стартовое время и возвращает фокус в «Фамилию». Нужна, например, если выбрали не ту подсказку. Неактивна, когда все поля пустые; в режиме «Редактирование» её нет.

**Web** — пока нет (см. «Ограничения»).

## Правила и граничные случаи

- **Откуда история.** Два источника, объединяются:
  - **локальная база Android** — все соревнования на устройстве, кроме текущего, удалённых и тестовых; подсказки есть сразу и без сети, включая ещё не выгруженных участников;
  - **сервер** — все соревнования, где пользователь владелец (`ownerId`), кроме текущего и тестовых, в том числе те, чей состав на это устройство не загружался (список «Мои старты» приходит с сервера без участников — состав скачивается, только когда соревнование открывают в Центре).

  Сначала показывается локальная история, серверная добавляется, когда придёт ответ. Нет сети или авторизации — остаётся локальная. Одна запись участника (по `id`, он одинаковый на клиенте и сервере) учитывается один раз, локальная версия важнее.
- **Тестовые соревнования** в историю не попадают (в них сгенерированные участники) — и при проверке на тестовом соревновании подсказки идут из обычных.
- **Один человек — одна подсказка.** Участия склеиваются по `userId` (человек регистрировался сам), а без него — по фамилии и имени с точностью до регистра, пробелов и «ё». Если такое имя ровно у одного зарегистрированного пользователя, ручные записи присоединяются к нему. Однофамильцы с разными `userId` остаются разными подсказками — различить их помогают команда, группа и дата.
- **Данные — из последнего участия**: команда и группа берутся из самого свежего соревнования.
- **Порядок**: сначала те, кто участвовал чаще, затем — недавно.
- **Уже в протоколе — не подсказываем** (совпал `userId` или фамилия с именем). Добавленный участник сразу пропадает из подсказок.
- Если после выбора подсказки поправить фамилию или имя, подсказки появятся снова, а добавление считается ручным (для аналитики).
- В режиме «Редактирование» подсказок нет.
- Номер чипа из прошлого не переносится: стартовый номер и чип назначаются по правилам текущего соревнования.
- `userId` в нового участника не переносится — запись создаётся так же, как при ручном вводе.
- **Массовое добавление** ставит людей по очереди в порядке списка (сначала частые): каждый следующий получает следующий номер и время с учётом уже добавленных — до жеребьёвки по стартовому интервалу группы, после — в ближайшую свободную минуту или в конец протокола, при старте по стартовой станции без времени. Если часть записей сохранить не удалось, показывается «Не удалось добавить K из N участников».
- Участник, удалённый локально, но ещё не удалённый на сервере (нет синхронизации), может попасть в историю из серверного ответа.

## Как устроено

**competra-server (eSport)**

- `GET /event/orienteering/participants/history?excludeCompetitionId=…` (JWT) — `OrienteeringRouting.kt`, `OrienteeringParticipantService.getHistoryByOwner`: `JOIN` участников с `competitions` по `ownerId`, без `isTest`. Ответ — `List<ParticipantHistoryResponse>` (`id`, `userId`, `firstName`, `lastName`, `groupName`, `commandName`, `competitionId`, `competitionDate`). Склейку и поиск делает клиент. Описан в `docs/API.md`.

**competra-android**

- `domain/.../models/orienteering/ParticipantHistory.kt` — `PastParticipation` (одно участие), `KnownParticipant` (человек), `ParticipantHistory.merge` (локальная + серверная), `aggregate` (склейка и сортировка), `excludeProtocol`, `search`. Тесты — `domain/src/test/.../orienteering/ParticipantHistoryTest.kt`.
- Локально: `OrienteeringParticipantDao.getParticipantHistory` — `JOIN` участников с соревнованиями (дата, фильтры `isDeleted`/`isTest`), проекция `ParticipantHistoryRow`; `OrienteeringCompetitionLocalRepository.getParticipantHistory`. Без миграции БД.
- Сервер: `OrienteeringCompetitionRemoteDataSource.getParticipantHistory` → `OrienteeringCompetitionRemoteRepository.getParticipantHistory` → `OrienteeringCompetitionInteractor.getServerParticipantHistory`. В Room не сохраняется.
- `ParticipantListViewModel.buildNewParticipant` — номер, время и чип нового участника по протоколу (общий для одиночного и массового добавления); `addParticipantsFromHistory` — действие `ParticipantListAction.AddParticipantsFromHistory`: собирает участников по очереди, пересчитывая протокол после каждого, сохраняет и закрывает диалог.
- `ParticipantListViewModel.loadParticipantHistory` — при `ShowCreateParticipantDialog`: локальная история в `ParticipantListState.participantHistory`, затем объединённая с серверной.
- `ParticipantListScreen` — `CreateParticipantDialogContent`: поля «Фамилия» → «Имя», кнопка «Очистить», отсев тех, кто уже в протоколе, поиск и блок `ParticipantHistorySuggestions`; `HistoryBulkSelectDialog` — массовый выбор, полноэкранный `Dialog` (без свайпа, закрытие — «Назад» / системная «назад»). В домене — `ParticipantHistory.filter` (список без лимита), `prioritizeGroup` (сначала текущая группа) и `keyOf` (ключ отметки, не меняется при добавлении серверной истории).

## Аналитика

- `participant_added` (`method`: `manual` — набрано вручную, `history` — выбрано из подсказки и имя не правили) — отправляется после сохранения участника из диалога «Новый участник».
- `participants_bulk_added` (`participants_count` — сколько сохранено) — одно событие на нажатие «Добавить в группу …»; `participant_added` для каждого при массовом добавлении не отправляется.
- «Очистить» — без события (действие только в интерфейсе).

## Ограничения и что не вошло

- **Web** — подсказок нет; серверный эндпоинт для этого уже есть.
- Массовое добавление — только в группу, для которой открыт диалог (не раскладывает людей по их прошлым группам); ручного времени дозаявки для пачки нет.
- Год рождения и пол в истории не хранятся, однофамильцы различаются только по команде, группе и дате.
- Соревнования, где пользователь организатор, но не владелец (`ownerId`), в серверную историю не попадают.
