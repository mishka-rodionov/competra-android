# Привязка результатов организатором и объединение дублей рейтинга

## Зачем

На прошлые соревнования участников вносили вручную. Потом люди зарегистрировались сами, но заявки на старые результаты подали не все. В итоге в рейтинге один человек оказывается в двух строках: «аккаунт» (новые старты) и «без аккаунта» (старые ручные записи). Ещё бывают ручные записи с разным написанием («Родионов М.» и «Родионов Михаил»). Теперь организатор исправляет это сам, не дожидаясь заявок.

## Как пользоваться

### Web

**Привязать одного участника** — «Управление» → вкладка «Участники»:
1. У участника без аккаунта под ФИО есть ссылка «Привязать к аккаунту».
2. В диалоге сразу ищутся аккаунты по фамилии участника. Можно ввести другое написание и нажать «Найти».
3. Выберите человека (видны год рождения и пометка «имя совпадает с протоколом») и нажмите «Привязать».
4. У привязанного участника видно «Привязан к профилю пользователя». Отвязать можно, как и раньше, в карточке участника («Изменить» → «Отвязать от профиля»).

**Объединить дубли в рейтинге** — страница рейтинга (видна админам клуба-владельца):
1. Блок «Похоже, это один человек» показывает строки с одинаковой фамилией и совместимым именем. Кнопка «Объединить» открывает диалог.
2. Если дубль не подсказан (например, опечатка в фамилии «Сеницкий»/«Синицкий»), выберите «Объединить записи вручную», отметьте строки и нажмите «Объединить (N)».
3. В диалоге выберите основную запись. По умолчанию это строка с аккаунтом, иначе — с самым полным именем. Нажмите «Объединить».

### Android

- **Привязать одного участника**: «Центр» → список участников. У карточки участника без аккаунта есть ссылка «Привязать к аккаунту», дальше всё как в вебе. Нужна сеть, и участник должен быть уже синхронизирован с сервером.
- **Объединить дубли**: экран рейтинга, для админа клуба. Карточка «Похоже, это один человек», кнопка «Объединить записи вручную» и чекбоксы у строк, диалог «Объединить записи» с выбором основной.

## Правила и граничные случаи

- Если основная строка — **аккаунт**, участники остальных строк привязываются к нему (`userId`). Человек получает пуш «Результаты привязаны к профилю» и может отвязать результат сам на экране своих привязок.
- Если обе строки **без аккаунта**, остальные записи переименовываются в протоколах в ФИО основной.
- **Два аккаунта** объединить нельзя. Если основной выбрана строка без аккаунта, а среди остальных есть аккаунт, сервер ответит «Основной выберите строку с аккаунтом».
- Операция **«всё или ничего»**. Если у аккаунта уже есть свой участник в одном из соревнований, ничего не меняется, и сервер сообщает, в каком соревновании дубль. Его нужно удалить и повторить. То же, если участник уже привязан к другому аккаунту.
- **Права**: `MANAGE_PARTICIPANTS` на **каждое** затронутое соревнование, а не только админство в клубе рейтинга. Админ клуба не может привязывать чужие протоколы.
- Заявки на привязку этих участников закрываются: заявка того же человека одобряется, чужие отклоняются («Результат привязан к другому пользователю»).
- Привязанного участника переименовать нельзя: его нужно объединять, а не переименовывать.
- Ключ строки рейтинга без аккаунта нормализуется: регистр, **ё/е**, лишние пробелы. «Изгарёв» и «Изгарев» — теперь одна строка без всякого объединения.
- Поиск аккаунтов: по фамилии или по «фамилия имя», от 2 символов, до 20 результатов. Email и телефон не отдаются.

## Как устроено

**API** (eSport, подробнее — `docs/API.md`):
- `GET /event/orienteering/participants/{id}/link-candidates?query=` — кандидаты (`LinkCandidateResponse`).
- `POST /event/orienteering/participants/link` `{userId, participantIds}` — привязка организатором.
- `POST /event/orienteering/participants/rename` `{participantIds, firstName, lastName}` — одно написание ФИО.
- `POST /ratings/{id}/standings/merge` `{ratingGroupId, targetKey, sourceKeys}` — объединение строк рейтинга. Сервер сам выбирает привязку или переименование.
- `GET /ratings/{id}/standings` дополнен: `userId`, `firstName`, `lastName` в строке, `participantId` в `breakdown[]`, `possibleDuplicates`.

**competra-server/eSport**
- `src/main/kotlin/data/services/ParticipantLinkRequestService.kt` — `linkCandidates`, `linkByOrganizer`, `renameByOrganizer`, `mergeStandings`.
- `src/main/kotlin/data/services/StandingDuplicates.kt` — поиск дублей (`firstNamesCompatible`, `findDuplicateGroups`), тест `StandingDuplicatesTest`.
- `src/main/kotlin/data/services/RatingService.kt` — `participantKey` с `normalizePersonName`, новые поля таблицы.
- `src/main/kotlin/data/routing/ParticipantLinkRouting.kt`, `RatingRouting.kt`.

**competra-web-ts**
- `src/features/participant-links/LinkToAccountDialog.tsx`, `src/features/management/ParticipantsManageTab.tsx`.
- `src/features/ratings/MergeStandingsDialog.tsx`, `src/pages/RatingDetailPage.tsx`, `src/features/ratings/RatingStandingRow.tsx`.
- `src/api/participantLinkRepository.ts`, `src/api/ratingRepository.ts`.

**competra-android**
- `:data:remote` — `ParticipantLinkRemoteDataSource`, `RatingRemoteDataSource`, мапперы `ParticipantLinks.kt`, `Rating.kt`.
- `:domain` — `LinkCandidate`, `RatingStandings`, `ParticipantLinkRepository`, `RatingRepository`.
- `feature/rating/.../presentation/detail/` — объединение в рейтинге.
- `feature/center/.../presentation/participant_list/` — «Привязать к аккаунту».

## Аналитика

Отдельных событий для привязки организатором и объединения пока нет.

## Ограничения и что не вошло

- Объединение работает внутри одной группы рейтинга. Если человек перешёл из М17 в М21, дубли в разных группах объединяются в каждой группе отдельно (привязка к аккаунту при этом действует сразу везде).
- Отвязать результат в Android-списке участников «Центра» нельзя. Для этого есть экран заявок и результатов.
- Слить два аккаунта нельзя.
