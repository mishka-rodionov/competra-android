# Регистрация на финише — дизайн-спека

Статус: **согласовано 09.11.2026; eSport, Android и web реализованы**. Порядок реализации: eSport → Android → web. Что сделано — [docs/features/finish-registration](../features/finish-registration/README.md).

> Отличия реализации от спеки: пол и год в карточке не вводятся (у участника соревнования нет таких полей); «Неразобранные считывания» — шторка на экране считывания, а не отдельный экран (экрана `center_unassigned_reads` в аналитике нет); «Засчитать по времени считывания» добавляет отметку финиша во время считывания и пересчитывает результат (ручной признак не ставится); режим можно переключать в мастере; ручной статус на экране результатов — не в первой версии. Смена группы с пересчётом, отвязка чипа и подсказка группы по отметкам добавлены 10.11.2026.

## Зачем

Запрос организатора («технический старт»): соревнование заводится без заранее зарегистрированных участников. Люди приходят на старт, получают чипы, стартуют по стартовой станции и бегут. На финише организатор считывает чип и только тогда вносит данные участника и его группу. Правильность прохождения организатор оценивает сам, места по группам считаются автоматически.

Аналог в SportOrg — настройка «Привязка чипа при считывании» (`system_assign_chip_reading`: выкл / только неизвестные участники / всегда / автосоздание участника) и флаг группы «Любая дистанция» (`is_any_course`). Отдельного режима «технический старт» там нет.

## Основные решения

- **Режим включается галочкой «Регистрация на финише» в мастере создания** — и на Android, и в вебе, одинаково. Хранится полем соревнования `isFinishRegistration: Boolean` и синхронизируется вместе с соревнованием. Проводить соревнование (считывать чипы и разбирать считывания) можно только на Android.
- **Старт только по стартовой станции** (`StartTimeMode.BY_START_STATION`). Когда галочка включена, способ старта фиксируется и не выбирается. Общий старт по секундомеру — не в первой версии.
- **Чипы индивидуальные**: номер чипа в соревновании не повторяется, одному человеку один чип. Считывание сопоставляется с участником по номеру чипа, как сейчас.
- **Незнакомый чип не теряется**. Считывание сразу попадает в очередь «неразобранных» и тут же предлагает карточку участника. Карточку можно закрыть и разобрать позже.
- **Дистанция по умолчанию не проверяется.** Если у группы участника есть дистанция, после привязки к участнику отметки проверяются по ней как обычно.
- **Группы создаются заранее в мастере** (одна группа обязательна, как и сейчас). Неожиданную группу можно добавить прямо из карточки участника.
- **Неразобранные считывания хранятся только на телефоне.** На сервер уходят уже созданные участники и их результаты, через обычную синхронизацию.

## Коды стартовой и финишной станций по умолчанию

У каждой электронной системы отметки есть стандартные коды стартовой и финишной станций. Они задаются в коде, в `PunchingSystem` (`:domain`):

| Система | Старт | Финиш |
|---|---|---|
| `SPORTIDUINO` | 240 | 245 |
| `SPORTIDENT`, `SFR` | пока не заданы | пока не заданы |
| `PENCIL`, `PUNCH` | — | — |

- Пример: `PunchingSystem.defaultStartStationCode: Int?`, `defaultFinishStationCode: Int?`. В KDoc enum'а напоминание: **при добавлении новой системы отметки задать её коды по умолчанию**.
- Правило (для всех соревнований, не только для этого режима): если у дистанции не задан `startControlPoint` / `finishControlPoint` или у группы вообще нет дистанции, берутся коды по умолчанию системы отметки соревнования.
- В форме дистанции поля старта и финиша предзаполняются этими кодами.

## Считывание на финише (Android)

Работает на экране считывания (`OrientReadCardViewModel`), если у соревнования `isFinishRegistration = true`.

1. **Чип известен** (есть участник с таким `chipNumber`): поведение как сейчас, включая конфликт при повторном считывании.
2. **Чип незнакомый**:
   - Считывание сохраняется в очередь: номер чипа, время считывания, clear time, отметки.
   - Если этот чип уже есть в очереди, запись обновляется, а не дублируется.
   - Открывается шторка карточки участника (см. ниже).
   - Если шторку закрыть, считывание остаётся в очереди, а на экране появляется плашка «Неразобранные: N».
3. Вне режима незнакомый чип обрабатывается как сейчас: только сообщение «Чип №N не найден».

### Карточка участника (шторка)

Два варианта:

- **«Новый участник»**:
  - **Обязательно**: ФИО (с подсказками по прошлым соревнованиям, как в «Новом участнике») и группа (выпадающий список + «+ новая группа»).
  - **Необязательно**: пол, год рождения, команда.
  - Номер участника присваивается автоматически (следующий свободный), `chipNumber` — номер считанного чипа, `isChipGiven = true`.
- **«Привязать к существующему»**: поиск по ФИО/номеру среди участников без результата, например предзарегистрированных без номера чипа. Участнику записывается номер чипа.

После сохранения результат считается (см. ниже), места в группе пересчитываются, запись удаляется из очереди.

### Экран «Неразобранные считывания»

- Вход: плашка на экране считывания и пункт в управлении соревнованием (Центр) со счётчиком.
- Список: номер чипа, время считывания, число отметок, время на дистанции (от стартовой до финишной станции, если обе отметки есть).
- Тап по строке открывает ту же карточку участника. Ошибочное считывание можно удалить из очереди (с подтверждением).

## Подсчёт результата

- **Время старта**: отметка стартовой станции (`distance.startControlPoint`, иначе код по умолчанию). Нет отметки — DSQ «Нет отметки на стартовой станции», как сейчас.
- **Время финиша**: отметка финишной станции (`distance.finishControlPoint`, иначе код по умолчанию).
- **Нет отметки финиша**: DSQ «Нет отметки финиша». На результате кнопка «Засчитать по времени считывания»: время финиша = время считывания чипа, статус пересчитывается (проверка КП по дистанции группы, если она есть), признак ручного статуса ставится. Для этого время считывания хранится вместе с результатом (до разбора — в очереди).
- **Группа без дистанции**: проверки КП нет, статус `FINISHED`, время = финиш − старт. Вне этого режима группа без дистанции по-прежнему не получает результат (см. `groups-without-distance`).
- **Группа с дистанцией**: обычная проверка по формату соревнования (заданный порядок / по выбору) и КВ.
- **Смена группы** у участника с результатом: результат пересчитывается по новой группе, места пересчитываются в обеих группах.
- **Ручной статус** (только в соревнованиях с `isFinishRegistration`): на результате кнопки «Снят» (→ DSQ) и «Засчитать» (→ FINISHED, если есть время). Ручной статус не перетирается автоматическим пересчётом, пока организатор его не вернёт. Признак ручного статуса нужно хранить и синхронизировать — поле уточнить при реализации (есть `isEdited`, но сейчас оно означает правку времени).

## Завершение соревнования

Если в очереди есть неразобранные считывания, перед «Завершить» показывается предупреждение «Осталось N неразобранных считываний — они не попадут в результаты» с действиями «Разобрать» / «Всё равно завершить».

## Мастер создания (Android и web)

- Галочка «Регистрация на финише» на шаге «Основное», с пояснением в одну строку. В вебе — в форме создания соревнования, с тем же поведением.
- Режим задаётся при создании. При редактировании соревнования (Центр на Android, «Общее» в вебе) он только показывается.
- Когда галочка включена:
  - способ старта зафиксирован («По стартовой станции»);
  - шаг «Дистанции» по-прежнему необязателен;
  - шаг «Группы» обязателен, как сейчас.
- Онлайн-регистрация не отключается: предзаявленные с номером чипа сопоставляются обычным образом.

## API (eSport)

- `isFinishRegistration` — поле в запросах и ответах соревнования, колонка в таблице соревнований (по умолчанию `false`). `null` в запросе — не менять, чтобы старые клиенты и веб не сбрасывали поле.
- Признак ручного статуса результата — поле результата (по итогам решения выше).
- Обновить `competra-server/eSport/docs/API.md`.

## Web

- Галочка в форме создания (см. «Мастер создания»).
- Поле приходит и сохраняется: при редактировании соревнования в вебе его не терять.
- В деталях соревнования — подпись «Регистрация на финише».
- Результаты показываются как обычно. Считывания и ручные статусы в вебе не делаются.

## Не в первой версии

- Общий старт по секундомеру.
- Повторная выдача чипов (несколько людей с одним чипом за соревнование).
- Настройка соревнования «Без отметки финиша — засчитывать по времени считывания» (автоматически, без кнопки).
- Ручные статусы «Снят / Засчитать» в обычных соревнованиях.
- Разбор считываний в вебе.
- Синхронизация очереди неразобранных между устройствами.
- Автоподбор группы по отметкам (как «лабиринт» в SportOrg).
- Коды стартовой и финишной станций по умолчанию для SPORTIDENT и SFR.
