# Формат (направление) на уровне дистанции — дизайн-спека

Статус: **согласовано 11.11.2026, к реализации**. Порядок реализации: eSport → Android → web.

## Зачем

Сейчас направление (`FORWARD` / `BY_CHOICE` / `MARKING`) и режим «по выбору» (`byChoiceMode`: `SCORE` / `MIN_CONTROLS`) задаются один раз на всё соревнование. Организаторы просят разные форматы в одном соревновании: например, М21 — в заданном направлении, М12 — по выбору.

## Основные решения

- **Формат — свойство дистанции.** Трасса определяет правила: баллы КП (`ControlPoint.score`) и минимум КП (`Distance.minControlsCount`) уже хранятся на дистанции. Если одну дистанцию бегут несколько групп, правила у них одинаковые. Если на одной трассе нужны разные правила — организатор делает вторую дистанцию.
- **У соревнования формат остаётся — как умолчание.** У дистанции два nullable-поля `direction` и `byChoiceMode`; `null` значит «как у соревнования». Старые соревнования и организаторы, которым фича не нужна, ничего не замечают; миграция — только новые nullable-колонки.
- **Эффективный формат группы** = формат её дистанции ?: формат соревнования. Группа без дистанции (или с удалённой) получает формат соревнования.
- **Места по-прежнему считаются по группе.** Меняется только то, откуда берётся формат.

```
effectiveDirection(distance, competition)  = distance?.direction   ?: competition.direction
effectiveByChoiceMode(distance, competition) = distance?.byChoiceMode ?: competition.byChoiceMode
ranksByScore(distance, competition) = ranksByScore(effectiveDirection, effectiveByChoiceMode)
```

`byChoiceMode` дистанции имеет смысл только при эффективном `BY_CHOICE`. Если у дистанции `direction = BY_CHOICE`, а `byChoiceMode = null`, режим берётся из соревнования, а если там нет «по выбору» — `ByChoiceMode.DEFAULT` (как сейчас).

## Контрольное время и его политика

КВ не меняется: задаётся на соревновании (`controlTimeMinutes`) с переопределением на группе (`timeLimitMinutes`).

Политика превышения КВ теперь зависит от **того, как ранжируется дистанция**, — две настройки соревнования:

| Настройка | Для каких дистанций | Значения | Умолчание |
|---|---|---|---|
| `timeOvertimePolicy` | места по времени: `FORWARD`, `MARKING`, `BY_CHOICE` + `MIN_CONTROLS` | `IGNORE` / `DISQUALIFY` | `IGNORE` |
| `scoreOvertimePolicy` | места по баллам: `BY_CHOICE` + `SCORE` | `IGNORE` / `DISQUALIFY` / `SCORE_PENALTY` | `SCORE_PENALTY` |

На дистанциях с баллами всё работает **как сейчас**: после превышения КВ группы начисляется штраф `scorePenaltyPerMinute` за минуту, после `maxLatenessMinutes` результат обнуляется (параметры — на группе).

### Совместимость по API

Поле `overtimePolicy` в API и БД остаётся и сохраняет нынешний смысл — **политика для формата соревнования по умолчанию**. Его читают старые клиенты, поэтому для соревнований с одним форматом всё работает как раньше.

- Новые клиенты отправляют все три поля: `timeOvertimePolicy`, `scoreOvertimePolicy` и `overtimePolicy` = политика того вида, к которому относится формат соревнования.
- При чтении (сервер и клиенты), если новых полей нет (соревнование создано до фичи):
  - `scoreOvertimePolicy = ranksByScore(соревнование) ? overtimePolicy : SCORE_PENALTY`
  - `timeOvertimePolicy = ranksByScore(соревнование) ? IGNORE : overtimePolicy`
- `SCORE_PENALTY` для дистанции по времени не применяется (трактуется как `IGNORE`) — защита от некорректных данных.

В домене (Android, web) у соревнования два уже разрешённых поля без `null`; legacy-разбор — в мапперах.

## Интерфейс

**Мастер / редактирование соревнования**
- Выбор направления остаётся, подпись — «Формат по умолчанию» с пояснением «Можно изменить для отдельной дистанции».
- Блок КВ: селектор политики для вида формата по умолчанию — как сейчас. Второй селектор («На дистанциях с баллами» / «На дистанциях по времени») появляется, когда есть хотя бы одна дистанция другого вида. В мастере шаг КВ идёт до дистанций, поэтому второй селектор виден при возврате на шаг; до этого действует умолчание из таблицы — оно совпадает с нынешним поведением.

**Редактор дистанции**
- Новое поле «Формат дистанции» одним списком: «Как у соревнования (…)», «В заданном направлении», «По выбору — по баллам», «По выбору — по количеству КП», «Маркированная трасса».
- Колонка баллов КП и поле минимума КП показываются по **эффективному** формату дистанции (сейчас — по формату соревнования).
- Если формат дистанции другого вида, чем у соревнования, — подсказка, какая политика КВ к ней применяется и где её поменять.

**Редактор группы**
- Поля штрафа (`scorePenaltyPerMinute`, `maxLatenessMinutes`) показываются, если дистанция группы ранжируется по баллам (как сейчас — без учёта выбранной политики). Группа без дистанции — по формату соревнования.

**Публичные экраны**
- В деталях соревнования при разных эффективных форматах дистанций — «Формат: разный по дистанциям», а формат указывается у каждой дистанции (вкладка «Дистанции»).
- Результаты, сплиты, live-результаты, HTML-протокол, график баллов: «показывать баллы» решается **по группе**, а не по экрану целиком.

## Что меняется по слоям

### eSport
- `distances`: колонки `direction`, `by_choice_mode` (nullable). `orienteering_competitions`: `time_overtime_policy`, `score_overtime_policy` (nullable).
- `ResultRanking.recalculateGroup` берёт формат и политику по дистанции группы.
- Пересчёт мест: при смене формата дистанции — группы этой дистанции; при смене формата соревнования или любой из политик — все группы (как сейчас); при смене дистанции у группы — эта группа.
- `CompetitionDetailResponse` / ответы дистанций — формат дистанции (исходное и эффективное значение).
- `docs/API.md`.

### Android
- `Distance` (+ Room-миграция, entity, мапперы, DTO), `OrienteeringCompetition` (две политики), общая доменная функция эффективного формата.
- `OrientReadCardViewModel.computeCheckResult`: алгоритм проверки отметок — по эффективному формату дистанции группы участника. Регистрация на финише без группы (`finishOnlyCheck`) — без изменений; после назначения группы проверка идёт по её дистанции.
- `OrienteeringCompetitionInteractor.recalculateRanksV2` и все экраны результатов/сплитов — формат по группе.
- Мастер создания: `DistanceEditor`, `ParticipantGroupCreator`, `ControlTimeBlock` (`CommonCompetitionFieldScreen`).

### Web
- Те же места: `lib/byChoiceMode.ts`, `DistanceDialog`, `DistanceDetailsDialog`, `CompetitionFormatFields`, `ControlTimeFields`, `ResultsTab`, `DistancesTab`, `lib/splitsTable.ts`, `GroupSplitsTablePage`.

### Не затрагивается
- Командный зачёт по очкам за места и рейтинг серии: считаются по местам. Способ `TIME` в группе с баллами — как сейчас (вне этой фичи).
- Mapper и парсеры IOF XML: импортированная дистанция получает `direction = null` (как у соревнования).
